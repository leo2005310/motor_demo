# ESP32-S3 Wi-Fi 步进电机控制器

本项目基于 PlatformIO 和 Arduino 框架，通过 ESP32-S3 与 ULN2003 驱动板控制 28BYJ-48 步进电机。开发板连接 Wi-Fi 后，可通过局域网网页、串口命令或 HTTP 接口控制电机。

## 主要功能

- 网页控制电机正转一圈、反转一圈和停止。
- 网页支持设置 1～15 RPM 转速（支持一位小数），并显示当前设定转速。
- 网页显示电机运行状态、Wi-Fi 名称、IP 地址和信号强度，每 3 秒自动刷新。
- 串口支持指定运动步数、圈数、方向和转速，以及查询电机状态。
- HTTP 接口支持运动控制、停止和状态查询，便于其他程序调用。
- 支持 Wi-Fi 自动重连、串口手动重连及网络信息查询。

## 硬件与接线

项目配置对应 ESP32-S3 N16R8（16 MB Flash、8 MB OPI PSRAM），使用 ULN2003 驱动板和 5 V 版本的 28BYJ-48 步进电机。

### 电机驱动板接线

断电后，按照下表连接：

| ULN2003 驱动板端子 | 连接位置 |
| --- | --- |
| IN1 | ESP32-S3 GPIO13 |
| IN2 | ESP32-S3 GPIO12 |
| IN3 | ESP32-S3 GPIO14 |
| IN4 | ESP32-S3 GPIO11 |
| 电源正极（通常标为 + 或 VCC） | 适合电机负载的 5 V 电源正极 |
| 电源负极（通常标为 - 或 GND） | 5 V 电源负极，并与 ESP32-S3 GND 相连 |
| 电机插座 | 28BYJ-48 电机的五线插头 |

开发板与驱动板必须共地。不要使用 ESP32-S3 的 GPIO 引脚直接给电机供电。表中的 GPIO 编号指芯片引脚名称，不是排针的物理序号。

### 开发板与电脑连接

对于当前使用的双 USB 接口开发板，使用支持数据传输的 USB 线，将标有 **COM** 的接口连接电脑。

本项目在 `platformio.ini` 中设置了：

```ini
-DARDUINO_USB_CDC_ON_BOOT=0
```

因此，程序的 `Serial` 日志和命令交互使用 UART0，通过开发板的 USB 转串口芯片与电脑通信。标有 USB / OTG 的原生 USB 接口在当前配置下不承担此串口日志输出。

Windows 中的 `COM4`、`COM5` 等是系统分配的串口名称，可能随连接情况变化；请以实际识别的端口为准。

## 配置 Wi-Fi

1. 编辑 `include/wifi_credentials.h`，将 `WIFI_SSID` 和 `WIFI_PASSWORD` 设置为实际的 **2.4 GHz Wi-Fi** 名称和密码。
2. 保存后编译并烧录程序。修改 Wi-Fi 配置后也需要重新编译、烧录。

`include/wifi_credentials.h` 已由 Git 忽略，避免将密码提交到仓库。如果该文件不存在，请创建它并填写以下配置：

```cpp
#pragma once

constexpr char WIFI_SSID[] = "YOUR_WIFI_SSID";
constexpr char WIFI_PASSWORD[] = "YOUR_WIFI_PASSWORD";
```

## 编译、烧录与串口监视

先安装 PlatformIO，可使用 VS Code 中的 PlatformIO 扩展。在项目目录的 PlatformIO 终端中执行以下命令。

### 编译

```powershell
pio run
```

编译只会生成固件，不会将程序写入开发板。

### 烧录

```powershell
pio run --target upload
```

如果自动选择的串口不正确，可手动指定。以下以 `COM5` 为例，请替换为实际端口：

```powershell
pio run --target upload --upload-port COM5
```

### 打开串口监视器

```powershell
pio device monitor
```

项目已设置串口波特率为 **115200**。也可以显式指定端口和波特率：

```powershell
pio device monitor --port COM5 --baud 115200
```

打开监视器后，按开发板的 **RESET / EN** 键可重新查看启动日志。程序启动时会输出芯片信息、Wi-Fi 连接情况和命令列表。Wi-Fi 连接成功后，还会打印网页访问地址。

按 `Ctrl+C` 退出串口监视器。

## 网页控制

将手机或电脑连接到与开发板相同的局域网，在浏览器中打开串口日志给出的地址，例如：

```text
http://192.168.1.100/
```

请使用开发板实际获得的 IP 地址。网页提供以下控制：

| 按钮 | 功能 |
| --- | --- |
| 正转一圈 | 正向运动 4096 半步 |
| 反转一圈 | 反向运动 4096 半步 |
| 停止 | 停止当前运动并关闭线圈输出 |
| 设置转速 | 将输入框中的 1～15 RPM 转速应用到电机，不改变运动目标 |

在转速输入框中填写数值（例如 `8.5`），点击“设置转速”后生效。待机时设置不会启动电机，后续正反转使用设定的转速；运行中设置会调整当前运动的转速。设置保存在内存中，重启后恢复默认 10 RPM。

网页每 3 秒查询一次状态，显示电机运行或待机状态、当前设定转速，以及 Wi-Fi 名称、IP 地址和信号强度。自动刷新不会覆盖正在编辑的转速。自定义步数仍可通过串口或 HTTP 接口设置。

## 串口命令

在串口终端输入命令并回车执行。表中的方括号表示可选参数，尖括号表示必填参数，实际输入时不需要括号。

| 命令 | 功能 |
| --- | --- |
| `help` 或 `?` | 显示命令列表 |
| `wifi` | 查看连接状态、IPv4 地址、子网掩码、网关、DNS、MAC、信号强度和信道 |
| `reconnect` | 断开并重新连接配置的路由器 |
| `motor cw [steps]` | 正转指定半步数，省略时为 4096 半步 |
| `motor ccw [steps]` | 反转指定半步数，省略时为 4096 半步 |
| `motor move <steps>` | 按带符号的半步数运动，正数正转、负数反转 |
| `motor rev <turns>` | 按带符号的圈数运动，支持小数 |
| `motor rpm <rpm>` | 设置转速，范围为 1～15 RPM |
| `motor stop` | 停止电机并关闭线圈输出 |
| `motor status` | 查看运行状态、设定转速、累计位置和剩余步数 |

示例：以下每行都是一条独立命令；验证每次运动时，等待其完成后再发送下一条运动命令。

```text
motor cw
motor ccw 2048
motor move 512
motor rev -2.5
motor rpm 8
motor stop
motor status
```

前四条命令分别表示正转一圈、反转半圈、正转 512 半步和反转 2.5 圈。第五条将转速设为 8 RPM。

## HTTP 接口

服务使用 HTTP 80 端口。以下路径均相对于开发板的 IP 地址。

| 方法 | 路径示例 | 功能 |
| --- | --- | --- |
| `GET` | `/` | 获取控制网页 |
| `GET` | `/api/status` | 获取 Wi-Fi 与电机状态 |
| `POST` | `/api/motor?steps=4096&rpm=10` | 按指定步数和转速运动 |
| `POST` | `/api/motor/speed?rpm=8.5` | 单独设置转速，不启动或重启运动 |
| `POST` | `/api/motor/stop` | 停止电机并关闭线圈输出 |

运动接口参数：

- `steps`：必填，非零整数，范围为 -1000000～1000000，单位为半步；正数正转，负数反转。
- `rpm`：可选，范围为 1～15；省略时使用当前设定转速。

单独设置转速的接口要求提供 `rpm`，范围为 1～15，支持小数。缺失、格式错误或超出范围时返回 HTTP 400，不修改转速。

状态接口返回 JSON，包含 `ssid`、`ip`、`rssi` 和 `motor`。其中 `motor` 包含 `busy`（是否运行）、`rpm`（设定转速）、`position`（累计半步位置）和 `remaining`（带方向符号的剩余半步数）。成功执行运动、调速或停止请求后，也会返回状态 JSON。

## 电机运行方式

- 使用非阻塞的八相半步驱动，主循环同时处理电机、网页请求和串口输入。
- 按 **4096 半步作为输出轴的标称一圈**，默认转速为 **10 RPM**，可设置范围为 **1～15 RPM**。
- 运动完成或执行停止后关闭全部线圈输出，不持续通电保持位置。
- 运动过程中收到新的运动指令时，以当前累计位置为起点设置新目标，替换尚未完成的运动，不进行指令排队。
- 位置是软件累计的步数，启动时从零开始，没有编码器反馈或自动回零功能，不能据此确认实际机械位置。

## 常见问题

### 串口监视器打开后没有输出

如果终端只显示 `Terminal on COMx | 115200 8-N-1`，说明监视器已打开，但尚未收到程序输出。可按以下顺序检查：

1. 确认 USB 线连接开发板标有 COM 的接口，并支持数据传输。
2. 确认监视器选择了实际串口，波特率为 115200。
3. 保持监视器打开，按一下 RESET / EN 键，重新观察启动日志。
4. 输入 `help` 并回车，检查程序是否响应。
5. 确认已经成功执行烧录，而不只是编译。

更换 USB 接口后，先退出原监视器，再选择新端口重新打开。

### Wi-Fi 连接失败或网页打不开

检查 Wi-Fi 配置文件中的名称和密码是否正确，以及是否已重新烧录。通过串口输入 `wifi` 查看连接状态，必要时输入 `reconnect` 重连。网页应使用串口打印的实际 IP 地址，手机或电脑需与开发板处于可互相访问的局域网。
